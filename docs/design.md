# Design

`mt` is a small German↔English translation model designed to be trained from
scratch on a single 8 GB consumer GPU in a reasonable amount of time. This
document records the main design decisions and their rationale.

## Scope and constraints

- **From scratch.** No pre-trained weights, no distillation from public
  translation models, no synthetic data generated by another model. The
  vocabulary, model weights and decoding logic are learned/implemented here.
- **Single GPU.** The reference run uses an 8 GB laptop GPU (RTX 4060).
  Everything must fit, including activation memory during training.
- **Bilingual.** One checkpoint translates both `de→en` and `en→de`; the
  decoder target language is selected with a leading language token.
- **Open data.** Training corpora are public and downloaded at runtime.

## Architecture

| Component        | Choice                                             |
| ---------------- | -------------------------------------------------- |
| Type             | Encoder–decoder Transformer (pre-norm)             |
| Layers           | 6 encoder + 6 decoder                              |
| `d_model`        | 512                                                |
| Attention heads  | 8 (head dim 64)                                    |
| Feed-forward     | SwiGLU, hidden size 1408 (≈ 4·d_model·2/3)         |
| Normalization    | RMSNorm                                            |
| Positions        | fixed sinusoidal (enc + dec self-attention)        |
| Embeddings       | shared source/target vocabulary, tied with output  |
| Vocabulary       | 32k SentencePiece unigram, byte fallback           |
| Parameters       | ≈ 61 M (weights tied, counted once)                |

Notes:

- **Pre-norm** keeps gradients well behaved without a warm-up-sensitive
  initialization.
- **SwiGLU** with hidden size `2/3 · 4 · d_model` matches the parameter count
  of a classic 4× ReLU feed-forward while training slightly faster in
  practice.
- **Tied embeddings** remove ~16 M parameters from the output projection,
  which matters at this scale, and regularizes the output layer.
- **Sinusoidal positions** are parameter-free and extrapolate reasonably;
  a learned variant is available through `model.positional: learned`.
- **Cross-attention** uses no positional bias: queries are decoder states and
  keys/values are encoder outputs.

### Parameter count

```
embedding/output (32 000 × 512, tied)          16.38 M
6 encoder layers × (4 · 512² + 3 · 512 · 1408)  19.27 M
6 decoder layers × (2 · 4 · 512² + 3 · 512 · 1408)  25.56 M
norms (30 × 512)                                ~0.02 M
total                                          ~61.2 M
```

Each decoder layer has both self-attention and cross-attention, so decoder
layers are larger than encoder layers. For comparison,
`Helsinki-NLP/opus-mt-de-en` has ~74 M parameters with a 58k vocabulary;
the two models are the same order of magnitude, which makes the benchmark
comparison meaningful (see `docs/benchmarks.md`).

## Tokenization

A single shared SentencePiece unigram model is trained on the concatenation
of source and target text. Special tokens follow the Marian convention:

| token   | id | purpose                                   |
| ------- | -- | ----------------------------------------- |
| `<pad>` | 0  | padding, ignored by the loss              |
| `<unk>` | 1  | unknown piece (byte fallback makes rare)  |
| `<s>`   | 2  | decoder start token                       |
| `</s>`  | 3  | end of sequence, appended to both sides   |
| `<2de>` | —  | decoder target-language token: German     |
| `<2en>` | —  | decoder target-language token: English    |

Sequence layouts:

```
source:       w1 … wk </s>
target input: <2en> w1 … wk
target label:      w1 … wk </s>
```

The shared vocabulary keeps the model compact and lets both directions share
subword statistics; the target-language token is the only direction signal,
following the multilingual NMT convention.

## Data pipeline

Raw corpora are downloaded as JSONL. The preparation step normalizes text
(HTML unescape, NFC, control/zero-width character removal, whitespace
collapsing), drops degenerate pairs (length, length-ratio and
letter-ratio filters), deduplicates exact pairs by CRC32 fingerprint, holds
out a uniform hash-based validation split, and tokenizes with a
multiprocessing pool.

The output is a flat `uint16` token stream per side plus `int64` offsets,
memory-mapped at training time. Batches are formed by:

1. shuffling indices with a per-epoch seed;
2. splitting each shuffled chunk by direction;
3. sorting within the chunk by combined length ("sortish" batching);
4. packing examples greedily up to `max_tokens` tokens per batch;
5. shuffling the resulting batches.

With `direction: both`, each pair is used in one direction per epoch and the
direction alternates across epochs, so both directions see every pair over
two epochs.

## Training

- AdamW (`β = (0.9, 0.98)`, `ε = 1e-9`), inverse-square-root learning-rate
  schedule with 4 000 warm-up steps, peak lr `d_model^-0.5` scaled by
  `lr_scale`.
- Decoupled weight decay 0.01 on matrices; embeddings and norms are exempt.
- Label smoothing 0.1, dropout 0.1, gradient clipping 1.0.
- bfloat16 autocast on GPUs that support it (the RTX 4060 does), FP32 master
  weights.
- Checkpoints are resumable (optimizer, step counters and RNG state) and the
  best validation-loss checkpoint is kept separately.

## Decoding

Greedy and beam search share an incremental decoder with key/value caches.
Cross-attention keys/values are projected once per source and reused for all
decoding steps; only decoder self-attention caches are reordered as beams
diverge. Beam scores use the GNMT length penalty
`((5 + len) / 6) ** alpha` with `alpha = 0.6` by default.

A live beam slot may be reused after it emits EOS. Finished hypotheses are
therefore stored in a separate top-k buffer rather than in the beam slots,
which guarantees the best finished hypothesis is never lost. `tests/` checks
that beam search matches brute force when the beam is wide enough.

## What is intentionally out of scope

- More languages or a many-to-many model. The pipeline supports a single
  pair; the language token design leaves room for more, but the released
  checkpoint is de↔en only.
- Back-translation and other synthetic data.
- Multi-GPU / distributed training. `torchrun` support can be added later if
  needed; the code is single-process by design.
